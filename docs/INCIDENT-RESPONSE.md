# INCIDENT-RESPONSE（事件响应流程）

## 严重级别

- **P0**：全站不可用 / 数据泄露 / 重大安全事故
- **P1**：核心流程不可用（如登录、支付、下单）
- **P2**：非核心功能受损或性能显著下降
- **P3**：低风险缺陷或局部体验问题

## 响应 SLA

- P0：5 分钟内响应，30 分钟内形成止损方案
- P1：10 分钟内响应，1 小时内形成止损方案
- P2：30 分钟内响应，当日给出修复计划
- P3：1 个工作日内确认并排期

## 标准流程

1. 发现与确认（监控/告警/用户反馈）
2. 分级与指挥（指定 Incident Commander）
3. 止损与修复（优先恢复服务）
4. 沟通与同步（内部与外部状态通报）
5. 复盘与改进（24-72 小时内完成 postmortem）

## 沟通规范

- 单线程更新，避免多渠道冲突信息。
- 关键时间点必须留痕（发现、分级、恢复、关闭）。
- 对外信息以事实为准，不做未经验证的承诺。

## 复盘要求

- 根因分析（技术 / 流程 / 组织）
- 影响范围与损失评估
- 修复动作与防复发措施
- Owner、截止日期与验收标准
